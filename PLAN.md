# Codex architecture refresh plan

**Prepared 2026-11-26.** This plan covers the repository configuration, workflow, verification and public-facing documentation. [BUILD.md](BUILD.md) records the original design and previous migrations. [The pre-refresh plan](https://github.com/subkoks/multi-agent-system-architecture-codex/blob/47146d3c297c3a1d5f322da2f2b008c4e51866fa/PLAN.md) preserves the earlier design.

## Audit and decisions

- **Configuration.** The current launcher checks in smoke and health request help or version output. CLI 0.171.0 returned success for a deliberately invalid config on both paths. The startup-config probe accepted valid input and rejected an unknown project key in a trusted disposable fixture.
- **Roles and tools.** The main session owns delegated work, integration and final decisions. Add a documentation researcher and a GitHub repository operator for two recurring evidence needs. Keep three concurrent children, protect the parent permission boundary and choose specialized tools only when the task warrants them. Remove ineffective role-level permission overrides confirmed in the tagged CLI source. Keep read-only role behavior explicit. [OpenAI subagent configuration](https://learn.chatgpt.com/docs/agent-configuration/subagents) · [CLI role override source](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/core/src/agent/role.rs#L34-L45)
- **Models and cost.** Retain model and provider inheritance so installed roles work with the selected account and client. Start with single-agent execution for short tasks, use focused delegation where it saves work, and record comparable time and usage before making a permanent routing change. [OpenAI models](https://learn.chatgpt.com/docs/models) · [Codex pricing](https://learn.chatgpt.com/docs/pricing)
- **GitHub.** The existing required check is named `validate`. Reuse local gates, cancel superseded PR runs and keep CI credentials scoped. Apply the framework's productivity, collaboration, application security, governance and architecture guidance at repository scale. [GitHub Well-Architected Framework](https://learn.github.com/well-architected/) · [Framework overview](https://github.com/github/github-well-architected/blob/main/docs/framework-overview.md) · [Governing agents](https://learn.github.com/well-architected/governance/recommendations/governing-agents)

## Hosted follow-up

The public repository requires `validate`, a pull request, linear history and a CodeQL result under its active ruleset. The audit confirmed the baseline `validate` run and did not verify CodeQL execution. Before a hosted rollout, review required human approvals, CodeQL status and private vulnerability reporting. The proposed About description, topics and social preview are ready for an authorized repository settings update. [Active ruleset](https://github.com/subkoks/multi-agent-system-architecture-codex/rules/24894904) · [Baseline validation](https://github.com/subkoks/multi-agent-system-architecture-codex/actions/runs/40229672313) · [Discoverability and social preview](reference/readme-design.md#github-discovery)

Work stays on a feature branch until the gate passes. A commit revert restores the repository configuration. Any later installation requires separate explicit approval and uses the documented manifest to restore previous files. Repository settings changes, publishing, provider benchmarks with paid or private data, and runtime installation require their own authorization.
